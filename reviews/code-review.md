## Confirmed observations and risks needing additional validation

- **R1 / P1 geometry interpretation:** `solid` (1163) appends independently oriented shells; no Boolean union is performed. The independent reader reports 371 edges with more than two incident triangles in the reference tray without canvas text, 264 in the pen tray. These are measured aggregate topology defects under 1e-5 mm coordinate welding, not evidence that every component is open or every slicer fails. Bins/wipes in the sample set have zero boundary/nonmanifold/inconsistent edges, but intersecting shells and self-intersections are not tested. Prioritize a robust union/validation strategy or explicitly supported slicer workflow; acceptance requires intersection checks and documented slicer results. Effort large.
- **R2 / P2 preview/export timing:** `queue` (2434) schedules rebuild on the next animation frame; `save` reads cached meshes but names them from current P. Same-function preview/STL arrays match in all 31 cases, but that does not test a UI revision race. Flush/await rebuilding or track a revision before exporting. Add a real-browser rapid-input/export test. Effort small–medium.
- **R3 / P2 invalid direct inputs:** native numeric handlers ignore blank/nonfinite values and clamp to range; blanks revert on blur. This is a useful safeguard. Geometry functions themselves do not validate finite inputs (NaN wall or sheet thickness propagates), and `seg=0` can cause unbounded sampling. These are developer/API risks, not demonstrated ordinary UI exploits. Add a shared bounded validator before future import/API features; never invoke builders with arbitrary unvalidated values. Effort medium.
- **R4 / P2 estimates and fit claims:** overlap corrections 995–1028, 1099, 1927, 2112 are heuristics, not a union-volume calculation. Displays multiply cm³ by 1.24 for PLA (2380, 2437, 2479). No comparison establishes the comment's 1–2% accuracy. Snap warnings predict “fall off” or “crack” without physical evidence and run even with snap disabled. Label estimates and fit badges as approximate, gate them on enabled features, and compare against sliced mass and physical fit. Effort small for copy, medium for validation.
- **R5 / P2 half-grid compatibility:** `footAxis` (1777) uses 21 mm pitch on each odd half-cell axis; integer axes retain 42 mm feet. Upstream corroborates 42 mm pitch/base gap and base profile but has a 3.75 mm top radius versus this implementation's 4 mm. No test demonstrates “drops onto a standard baseplate” (2427), especially half-grid combinations. Document implementation dimensions and test actual baseplate seating; do not claim a universal standard. Effort small docs, medium physical trials.
- **R6 / P2 performance:** builders and text rasterization are synchronous; 160 ms edge debounce only postpones edge generation, not mesh building. Rendering loops continuously (2271); each view/available-height change queues a full build. Geometry replacement calls dispose, so no leak is established. Sample large 6×6 bin has 125,648 cleaned triangles; finest tested bin has 94,428. Long unrestricted labels can allocate large canvas/rectangle meshes. Profile repeated builds including canvas and EdgesGeometry, cap text/triangle budgets, and cache meshes when only the view changes. Acceptance: measured latency/memory and usable cancellation or busy feedback. Effort medium.
- **R7 / P3 lip semantics:** body lip tip choices go through `pushTip` (1189); lids always use rounded `tipLevels` (1655, 2072), regardless of flat/sharp selection. Clarify “body lip tip” or deliberately apply consistent style. `lip=false` bin still has a lid export and snap badge. This is confusing scope, not proof of a broken lid. Effort small.

## Recommended order

Fix C1–C4 before relying on exports for dimension-sensitive prints; fix C5–C10 in focused patches. Address R1 with independent mesh and slicer evidence, then performance and fit calibration. Keep the existing HTML/Three.js stack and simple visual layout. A dependency upgrade alone will not fix geometry or state bugs.
